# App Store 出荷品質との差分分析 — 100項目

> 作成: 2026-06-04 / 前提の更新: **現コードベースはプロトタイプ**と定義。ゴールは **App Store 販売**、
> 品質基準は **Gallop Racer の現代版**。最重要目標は「レース画面を見た瞬間に**本物の競馬みたい**と言われること」。
> 優先順位: ①レース中ビジュアル ②東京競馬場完全再現 ③馬モデル ④騎手モーション ⑤カメラ演出 ⑥実況 ⑦キャリア。
> **映像体験 ＞ レースロジック**（検証済み物理は"設計資産・参照値"へ位置づけ変更）。

## 前提となる最重要判断（この分析が突きつける分岐）

現プロトタイプは **単一HTML / Three.js r128 / 全プロシージャル生成（アセット・テクスチャ・ポストFX ゼロ）**。
旧ロードマップ（AAA_roadmap.md）は「単一HTML/ブラウザ＝最大の武器、ネイティブ却下」を根幹に置いていたが、
**新ゴール（App Store販売・映像最優先・写真級）はその前提を反転させる**。「本物の競馬みたい」は
旧ロードマップ自身が **"真のWeb天井"（骨格忠実モデル＋抑揚ある実況音声）** と認めた領域であり、
**プロトタイプの延長線では到達しない**。よって本分析の第1の結論は技術ではなく経営判断：

- **路線A：本エンジン移行（Unity / Unreal）** — 写真級・App Store最短。物理/AI/カメラ/実況のJS資産は"設計仕様"として移植。律速は3Dアーティスト/モーション工数。
- **路線B：Web重武装（WebGL2/WebGPU + r16x + スキンドGLTF + フルポストFX）を Capacitor 等でネイティブ梱包** — 既存JS資産を活かせるが、写真級はツール/性能で不利、実質エンジン級工数。
- 以降の②〜⑦の作り込みは **路線確定が前提**（同じ作業をどの土台でやるかが変わる）。

## A. レース中ビジュアル・描画技術（優先①＝出荷の主戦場）

1. **ポストプロセス基盤が皆無**（renderer.render 直叩き、EffectComposer なし）→ HDRパイプライン必須。
2. **Bloom なし** → 西日・ゴール板・ビジョンの発光。
3. **被写界深度(DoF)なし** → ゴール前の鼻先フォーカス・背景ボケ（シネマ感の核）。
4. **モーションブラー なし** → 疾走の速度感。
5. **アンビエントオクルージョン(SSAO/GTAO)なし** → 接地と陰影の密度。
6. **カラーグレーディング(LUT)なし**（現状 ACES のみ）→ 「中継の色」の統一トーン。
7. **濡れ路面/スクリーンスペース反射なし** → 雨・稍重のリアリティ。
8. **ボリュメトリックライト(西日の光芒)・大気散乱なし**。
9. **霧が単純 linear Fog(0x202a3a,150,600)** → 高度・距離の大気遠近の作り込み不足。
10. **HDRI環境マップが canvas 手続き生成（低品質）** → 実HDRIベースIBL。
11. **PBRテクスチャ皆無**：全マテリアルがフラット色 MeshStandardMaterial。albedo/normal/roughness/AO/metalness が無い。
12. **法線マップによる微細ディテール（芝・馬体・スタンド・ゲート）なし**。
13. **シャドウが全メッシュ一律 castShadow の PCF** → カスケードシャドウ(CSM)・解像度/バイアス・主役限定が未整備。
14. **接地影が blob スプライト併用の簡易** → 本影＋接地AOの質不足。
15. **芝が平面＋canvasストライプ** → GPU草・刈り目・踏み跡。
16. **砂煙が60枚スプライトプール** → GPUパーティクル（蹄ごとの土塊・砂・芝片・飛沫）。
17. **馬の汗・湯気・鼻息・息白なし**。
18. **路面の蹄跡・ターフ剥離・ダート飛散の堆積表現なし**。
19. **ライティングが Hemi+Ambient+1方向光の簡易** → 時間帯/天候プリセット・GI近似。
20. **反射プローブ/局所反射なし**（金属ゲート・ビジョン・馬体の艶）。
21. **品質AA未整備**（MSAA/FXAA/TAA 未明示）。
22. **動的解像度/アップスケールが予算オーケストレーターの簡易調整のみ**。
23. **セカンダリモーションが手続きsin**（尾・たてがみ・筋肉）→ 物理/ボーンベース。
24. **画面効果がCSSビネットのみ**（色収差・ヒートヘイズ等のシーン内ポストへ）。
25. **総体として"2世代前の試作見え"**（旧roadmap自認）→ 最低Switch級、ゴール前はPS4級の瞬間。

## B. 東京競馬場 完全再現（優先②）

26. **コースがオーバル**（周長1599.6m）→ 東京実測（周長約2083m・直線525.9m・複合カーブ）。
27. **高低差ゼロ（平面）** → ゴール前の坂（標高プロファイル）を描画＋物理。
28. **複合カーブが二値 curveAt** → クロソイド（曲率連続）。
29. **距離別スタートが startS 連続後退ロジック** → JRA実配置の離散（2角ポケット等）。
30. **フジビュースタンドなし**（box＋発光テクスチャ）→ 実スタンド形状。
31. **大型ターフビジョンなし**。
32. **内馬場・池・芝模様・ゴール板・ハロン棒・コース柵のディテールなし**。
33. **パドック・装鞍所・本馬場入場の動線なし**。
34. **視覚的群衆ゼロ**（歓声は音のみ）→ GPU instancing の群衆（数千）・アニメ。
35. **写真判定ライン/着順掲示の実物再現なし**。
36. **背景（都心ビル・けやき・空）再現なし**。
37. **馬場状態の見た目分岐が色差のみ** → 路面質感・水たまり・蹄跡の差。
38. **芝/ダート併設なし（芝のみ）**。
39. **時間帯・照明（晴/曇/薄暮/ナイター）再現なし**。
40. **実測寸法・出典管理（クロソイド係数・坂勾配）なし** → 権利/likeness の検討含む（J項参照）。

## C. 馬モデル刷新（優先③）

41. **馬がプロシージャル楕円体/円柱（~50メッシュ）** → スキンドメッシュ（GLTF/Draco）骨格忠実モデル。
42. **筋肉のうねり・骨格・腱なし** → スキニング＋ブレンドシェイプ。
43. **毛のレンダリングなし（フラット色）** → 毛流れ/異方性反射/ファーシェーディング。
44. **顔のディテール（目の濡れ・鼻孔・口元）不足**。
45. **たてがみ・尾が箱/円柱** → 物理/専用シェーダの房。
46. **馬装が簡易プリミティブ** → 実物テクスチャ＋金具質感。
47. **毛色が6色フラット** → 実毛色＋差し毛/白徴のテクスチャ。
48. **LOD未整備（全頭フル）**。
49. **個体差が色のみ** → モデル/テクスチャの体格差。
50. **息・汗・耳/尾の反応なし**。
51. **接地IK未実装（脚が地面を貫通/浮き）**。
52. **ギャロップが手続きsin位相** → モーションキャプチャ（常歩/速歩/駈歩/追い出し/疲労）。

## D. 騎手モーション刷新（優先④）

53. **騎手が箱胴＋腕＋帽** → 多関節リグの人体。
54. **追い出しが lean の sin** → 両腕で手綱をしごく本格モーション。
55. **ムチが未描画** → 振り上げ→打ち下ろす1アークの専用モーション。
56. **手綱が馬と未接続** → 手綱IK/物理。
57. **騎乗フォームのステートマシンなし**（追走/折り合い/仕掛け/ゴール）。
58. **鐙・重心・モンキー乗りの姿勢再現なし**。
59. **騎手個性（フォーム差・利き手）なし**。
60. **勝利モーション（ガッツポーズ/スタンディング）なし**。

## E. カメラ演出（優先⑤）

61. **3固定 lerp（chase/jockey/overhead）** → 中継風オートディレクター（カット割り）。
62. **ゴール前の鼻先ズーム/ラックフォーカスなし**。
63. **TV/ヘリ/パン/ドリーの中継語彙なし**。
64. **写真判定が2Dフラッシュ的** → サイドライン→フリーズ→シャッターのシネマ。
65. **スローがtime-scaleのみ** → カメラ連動の本格スロー。
66. **イントロ確立ショット/ヒーローカメラなし**。
67. **レンズ感（画角・歪み・収差）演出が簡易**。
68. **自馬とライバルを常にフレーム保持する構図保証なし**。
69. **リプレイ機能なし**。
70. **被写体予測（先読みフレーミング）が単純lerp**。

## F. 実況・音響（優先⑥）

71. **実況が Web Speech 合成** → プロ収録 or 高品質ニューラルTTS。
72. **声の抑揚が機械的** → 中継のテンション再現。
73. **効果音が全て合成**（蹄音/地鳴り/歓声/ベル）→ 実録サンプル（芝/ダート蹄音・多頭・風）。
74. **空間オーディオなし** → 3D定位（PannerNode/HRTF）。
75. **BGM/アンダースコアなし**。
76. **歓声が単一ノイズ層** → 多層・盛り上がりカーブ。
77. **ミックス/ダッキング設計なし**（実況・歓声・BGMの帯域競合）。
78. **固有名詞（馬名/レース名）の読み上げ品質が不安定**。

## G. キャリアモード（優先⑦）

79. **localStorageの単純戦績** → 年間スケジュール・番組表・シーズン制。
80. **レースの格（条件/OP/G3/G2/G1）・固定名G1なし**。
81. **騎乗依頼システム（人気薄 vs 本命）なし**。
82. **宿命のライバル・厩舎信頼・リーディング争いなし**。
83. **騎手育成が4スキルの簡易** → 成長/称号の深み。
84. **血統・馬の所有/育成要素なし**。
85. **セーブがlocalStorageのみ** → クラウドセーブ/複数スロット。

## H. エンジン・技術基盤・性能（横断）

86. **【最重要】配信がWeb/PWA** → App Store ネイティブ。r128単一HTMLで写真級は天井。**本エンジン採否が分岐**。
87. **WebGL1相当** → 写真級は WebGL2/WebGPU/r16x または本エンジンが前提。
88. **物理/AIがフレーム依存・単一スレッド** → 描画と分離（固定ステップ/ジョブ化）。
89. **アセットがゼロ（全手続き生成）** → アセット駆動への全面移行。
90. **60fps保証が解像度調整のみ** → 端末ティア別LOD/カリング/Occlusion。
91. **ドローコール/メモリ管理が未整備（全メッシュ個別）** → インスタンシング/バッチング/アトラス。
92. **テストが物理回帰中心** → ビジュアル回帰・実機GPUプロファイル。
93. **CIが静的配信のみ** → ネイティブビルド/署名/TestFlight。

## I. アセット制作パイプライン

94. **3Dアーティスト工数ゼロ前提** → リグ付きサラブレッド・モーションキャプチャ・東京スタンドのモデリング体制。
95. **テクスチャ/マテリアルのオーサリング（Substance等）なし**。
96. **オーディオ収録（実況/効果音/BGM）の制作体制なし**。
97. **アセット最適化（Draco/KTX2/圧縮/LOD生成）の自動化なし**。

## J. App Store / 事業要件

98. **ストア要件未対応**（IAP/課金・年齢区分・プライバシー・Reviewガイドライン）。
99. **収益モデル未設計**（買い切り/F2P/IAP/広告）・ストアページ（スクショ/動画/ASO）未整備。
100. **法務**：現状「架空」明記。だが **東京府中"完全再現"は実在競馬場の表現・JRA/商標・likeness の権利検討が必須**（架空コース前提の設計と矛盾し得る）。

## 次のアクション（提案）

1. **路線A/Bを決める**（この分析の第1分岐。決めないと②〜⑦の作業土台が定まらない）。
2. 路線確定後、**優先①「レース中ビジュアル」で"本物の競馬みたい"の縦スライス**を1本作り、最初の "Wow" を最短で立てる（例：東京の直線1カットを写真級で）。
3. それを基準に②〜⑦を肉付け。物理は"参照仕様"として移植。
